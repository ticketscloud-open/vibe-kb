E2E-тесты мобильного приложения **Vibeapp** (React Native, Android) построены на [Maestro](https://maestro.mobile.dev): сценарии описываются YAML-флоу, прогон идёт на debug-сборке с Metro; сценарии с контентом и авторизацией выполняются против stage-бэкенда.

> [!info] Это снимок, а не живой документ
> Заметки раздела — слепок состояния на **2026-09-29** с ветки `develop` репозитория `vibe-mobile`. Канонические документы живут там (`docs/maestro.md`, `docs/rtm.md`, `docs/test-cases/`, `docs/screen-inventory-xmind.md`) — при расхождениях верить репозиторию.
> Раздел охватывает E2E-тесты на Maestro и будет расширяться: нагрузочное и API-тестирование появятся отдельными подразделами

## Масштаб

| Метрика | Значение |
|---|---|
| Тест-кейсов + бизнес-инвариантов | **94** (90 TC + 4 инварианта, приоритеты P0–P2) |
| Maestro-флоу в прогоне | **90** — по одному файлу на TC (правило «1 TC = 1 flow») |
| Переиспользуемых под-флоу (`flows/`) | 8 — сами не запускаются, в покрытие не считаются |
| Экранов в приложении | ~67 |
| `testID` в коде | ≈75, из них ~50 используются тестами |
| Домены | онбординг, авторизация, лента, билеты, чаты, избранное, профиль, навигация |

## Глоссарий

| Термин | Значение |
|---|---|
| **TC** | Test Case — карточка сценария из каталога `docs/test-cases/`, ID вида `TC-TKT-04` |
| **Инвариант (I1–I4)** | бизнес-правило, защищаемое тестом (например I1: чаты доступны только владельцу билета) |
| **Flow** | один YAML-файл Maestro; «тест» в терминах прогона |
| **Под-флоу** | YAML из `flows/`, подключается через `runFlow`; сам не запускается и тегов не имеет |
| **RTM** | матрица трассировки «TC → flow → глубина проверки» (`docs/rtm.md`) |
| **testID** | prop React Native-компонента; Maestro находит элемент селектором `id:` по нему |
| **depth** | глубина проверки TC: `deep` / `shallow` / `shell` / `none` |
