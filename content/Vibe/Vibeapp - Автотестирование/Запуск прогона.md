Тесты гоняются на **debug-APK + Metro** (JS грузится из бандлера, не из APK), проверено на Maestro **2.6.1**; сценарии с контентом и авторизацией выполняются против stage-бэкенда

## Предусловия

- macOS, Android SDK и эмулятор — подойдёт любой профиль; тесты верифицированы на **Pixel_6_Pro**
- Node.js, пакетный менеджер `bun`
- Доступ к репозиторию `vibe-mobile`
- Установленный Maestro: `curl -Ls "https://get.maestro.mobile.dev" | bash`

## Пошагово

```bash
# 1. Зависимости и debug-APK
cd vibe-mobile
bun install
./gradlew assembleDebug        # артефакт: android/app/build/outputs/apk/debug/app-debug.apk

# 2. Эмулятор + установка
emulator -avd Pixel_6_Pro &
adb install -r android/app/build/outputs/apk/debug/app-debug.apk

# 3. Metro + проброс порта
npx react-native start &
adb reverse tcp:8081 tcp:8081
# прогреть бандлер: открыть http://localhost:8081/index.bundle — до появления бандла < 10 c

# 4. Тесты
maestro test .maestro/
```

## Локальный `.env` для E2E-прогона (обязателен)

Файл `.env` в корне `vibe-mobile` (в `.gitignore`). Минимум для E2E:

```text
VIBE_APPMETRICA_API_KEY=<любой UUID-плейсхолдер>   # иначе red box "AppMetrica isn't initialized"
VIBE_VERSION=0.0.0-e2e
VIBE_E2E=true                                       # отключает LogBox-тост, перекрывающий кнопки
```

После правок `.env` — перезапуск Metro с `--reset-cache`.

## Фильтрация прогона

```bash
maestro test .maestro/                            # полная регрессия
maestro test .maestro/auth/auth-login-empty-state.yaml   # один файл
maestro test .maestro/ --include-tags=smoke       # быстрый smoke-гейт
maestro test .maestro/ --include-tags=feed        # только домен «Лента»
maestro test .maestro/ --exclude-tags=backend     # без stage-зависимых тестов
```

`--exclude-tags=backend` — режим «нет доступа к stage», а не «нестабильные тесты»: большинство backend-флоу стабильно проходят на stage

## CI

Автотесты запускаются локально (см. выше). Workflow `e2e.yml` для Maestro в CI существует, но приостановлен: на github-hosted раннере (2 vCPU / 7 ГБ) эмулятор нестабилен — ANR «System UI isn't responding» гостевой ОС, к самим тестам отношения не имеющий. Сборка APK в CI при этом стабильна. Запуск — только вручную (`workflow_dispatch`, нужен секрет `VIBE_APPMETRICA_API_KEY`). Открытый вопрос: более мощный или self-hosted раннер. Полная история попыток и анализ — `docs/ci-proposal.md` в репозитории

## Практические грабли

- **Окно эмулятора должно быть развёрнуто на экране** — свёрнутое окно не даёт прогону стартовать и даёт ложные «Element not found» (экран не перерисовывается)
- **Кириллица не вводится** через `inputText` на Android (ограничение Maestro, [mobile-dev-inc/maestro#146](https://github.com/mobile-dev-inc/maestro/issues/146)) — в тестовых данных использовать ASCII (`rock`)
- **`hideKeyboard` на Android = системная кнопка «Назад»**: на экране логина уводит назад на профиль, на корне таб-навигатора — выгружает приложение на домашний экран. В тестах не применяется: клавиатура закрывается тапом по другому элементу
- **Runtime-разрешения**: `launchApp` грантует их не всегда успевая — для флоу с `clearState: true`, ведущих к экрану с запросом permission, ставить явно `setPermissions: { permissions: { notifications: allow } }`
- **Холодный Metro после смены `.env`** ломает прогон на онбординге, пока бандлер не прогрет — первым шагом полного прогона всегда ждём первый bundle (таймаут до 90 с)
